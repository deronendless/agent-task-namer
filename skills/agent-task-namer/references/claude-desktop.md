# Claude Desktop Code: local sessions

Use this path when the actual Claude Desktop Code host exposes official `get_session` and `set_session_title` tools supporting the current-session selector. Discover the actual tools from the host catalog; do not invent a namespace or endpoint. This path requires no Python SDK. The startup reminder still needs Python 3.

1. Read `get_session` with `session_id: "self"`. Confirm a local session and that its `cwd` agrees with the trusted current project. Use the returned Desktop `sessionId`, `title`, and ISO `createdAt`. The hook's runtime UUID and the Desktop session ID are different identities; never substitute one for the other, enumerate sessions to choose a target, or use SDK metadata to fill a missing Desktop creation time.
2. Apply the common naming rules to the actual conversation. Automatic naming requires a trusted `startup`, the first substantive request, and no existing conversation history; preserve known user-chosen titles, already-correct titles, and external title changes. A non-empty Desktop `title` alone is not evidence of a manual rename. Do not query the CLI SDK's `custom_title` as a Desktop eligibility check: it merges manual and AI-generated titles and does not describe Desktop title ownership.
3. Re-read `get_session("self")` immediately before writing. If the identity or title changed since inspection, preserve it and reassess. Call `set_session_title` with `session_id: "self"` and `title` set to the candidate, then read `get_session("self")` again. Never populate the App-managed `_consent` argument or bypass its protection for user-set titles; an automatic reminder does not authorize overriding one. Only the same `sessionId` and exactly matching `title` verify the Desktop change. Follow the main workflow's bounded retry rule; this check is not an atomic lock against concurrent user renaming.

If the native tools are missing, do not support `self`, or reject the current-session operation, preserve the Desktop title and offer a candidate. Do not substitute the SDK bridge, another session, private storage edits, or UI automation to get around that limitation. Desktop Chat, Cowork, cloud sessions, and Claude batch/restore are outside this workflow.

During maintenance, also verify the visible sidebar/header, ordinary follow-up, and reopening; a successful SDK write alone cannot establish Desktop synchronization. See the official [Desktop session management reference](https://code.claude.com/docs/en/desktop#manage-sessions).
